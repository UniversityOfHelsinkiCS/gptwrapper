# Accessibility statement of CurreChat of the University of Helsinki

This accessibility statement applies to the accessibility of CurreChat, an AI chat service for teaching and studying, available at [curre.helsinki.fi](https://curre.helsinki.fi). It also applies to CurreChat when it is embedded in Moodle. The document was created on 16 October 2026 and last updated on 10 November 2026. The accessibility analysis of the software was done by the developers using both automated tools ([WAVE Evaluation Tool](https://chrome.google.com/webstore/detail/wave-evaluation-tool/jbbplnpkjmmeebjpijfedlgcdilocofh) and [axe-core](https://github.com/dequelabs/axe-core) run with [Playwright](https://playwright.dev/)) and manual testing methods, including code review, keyboard testing and screen reader testing. In addition, the AI coding assistant [Claude Code](https://claude.com/claude-code) by Anthropic was used to support the evaluation, for example in reviewing the source code against WCAG requirements and in identifying accessibility issues. All findings were verified by the developers.

In November 2026, Gofore carried out an accessibility audit of the service, and its findings have been recorded in this accessibility statement. The audit evaluated the service against the EN 301 549 v4.1.1 standard, which includes, among other things, the WCAG 2.1 and the new WCAG 2.2 requirements at levels A and AA.

## Accessibility status

The system partially meets the A and AA level accessibility requirements of the EN 301 549 v4.1.1 standard, which includes the requirements of the Web Content Accessibility Guidelines (WCAG) 2.1 and WCAG 2.2. The accessibility deficiencies identified are described in detail below. The admin and statistics views were not included in the audit and have not yet been systematically evaluated.

## Accessibility issues

This list includes the issues that have been identified in the accessibility evaluation by the developers in autumn 2026 and in the accessibility audit by Gofore in November 2026. The evaluation is still in progress and the developers are actively working towards remediating the issues.

### Perceivability issues

- The documents that are downloadable from the service (in this case PDF, .doc) are not fully accessible (WCAG 1.3.1). Also a possible mismatch with EN 301 549 section 5.4 Preservation of accessibility information during conversion.
- Answers in the chat are generated by an AI model, and the developers cannot fully control their structure. Mathematical formulas are rendered with KaTeX and are also provided as MathML, but they are not read correctly by all screen readers. Formulas that fail to render are shown as raw LaTeX code. (WCAG 1.1.1, 1.3.1)
- In the usage trend chart on the statistics page, the data series are distinguished by colour alone. In the prompt usage chart in the course view, the colours repeat when a course has many prompts, so different prompts can have the same colour; the same data can be viewed as a table instead. (WCAG 1.4.1)
- When the service is used at a viewport width of 320 px or an equivalent zoom level (400% at 1280 × 1024 px), the side menu does not fit entirely within the viewport. With some devices, hiding the side menu couldn't be done for this reason at all. (WCAG 1.4.10)
- There are some important graphical/UI elements that do not meet the contrast requirements in both the light and dark mode. (WCAG 1.4.11)
- The prompt use graph info window is presented on hover. However, the user cannot move the pointer over the window, because this will change the data point and thus the content of the info window. (WCAG 1.4.13)

### Operability issues

- Toast notifications cannot be reached with a keyboard or a screen reader while a dialog is open. (WCAG 2.1.1)
- In the service, there are instances where an error message (or other information that cannot be inferred from elsewhere) is presented only in a toast notification. (WCAG 2.2.1)
- There are some instances in the service, where keyboard focus should be transferred to a certain place to ensure keyboard usability. (WCAG 2.4.3)
- The toast notifications are in the end of the page in focus order, which makes it difficult to find them in keyboard use. (WCAG 2.4.3)
- Focusable elements, such as the Information and settings button, are obscured by floating toast notification content. When the view is zoomed to 400%, there are many floating elements that hide content in keyboard focus. (WCAG 2.4.11 \*WCAG 2.2 requirement)
- Toast notifications disappear automatically after about 20 seconds. The timer pauses while the keyboard focus or the mouse is on a notification, but it does not pause while a screen reader user reads the page with the virtual cursor. The timing cannot be changed by the user. Notifications are not stored anywhere after they disappear. At most four notifications are shown at a time: when a fifth one arrives, the oldest disappears immediately and can no longer be focused or read. (WCAG 2.2.1)

### Understandability issues

- Some content is in a different language from the page, and this cannot be programmatically determined. This includes some English texts that have not been translated, the language options in the language menu, and AI answers written in a different language from the user interface. (WCAG 3.1.2)
- In some forms, errors are shown only in a notification and the invalid field is not marked. Examples: saving a prompt, managing notifications, and creating source material. In the course activity period, invalid dates typed into the date fields are ignored without an error message (WCAG 3.3.1, 3.3.3)

### Robustness issues

- Some screen readers may read some messages twice. For example, when generating an answer fails, the error can be announced several times, and new notifications are read together with recent ones. Notification banners interrupt the screen reader every time the service is opened or the page is reloaded, even when their content has not changed. (WCAG 4.1.3)

### Accessibility features already in place

To help users, the following features have been implemented:

- While an answer is being generated, its status (processing, writing, ready, cancelled, failed) is announced to screen readers. The answer text itself is not read out piece by piece.
- A "Skip to content" link at the start of every page moves the keyboard focus past the header, and in the chat also past the sidebar. The sidebar is marked as a landmark.
- The "Skip to latest response" button moves the keyboard focus to the newest answer.
- The user's questions and the answers received in the chat are numbered and have headings that are visually hidden but available to screen readers, so the conversation can be navigated by headings.
- Mathematical formulas in AI answers are also provided as MathML for screen readers.
- The user can choose whether Enter or Shift+Enter sends a message.
- A dark mode is available in the settings.
- All interactive elements have a visible keyboard focus indicator, and it has enough contrast in both light and dark mode.
- The selected tab, the usage gauge and the colours, axes and legends of charts have enough contrast in both light and dark mode.
- Notifications are announced to screen readers, also while a dialog is open.
- The prompt usage chart in the course view can also be shown as a data table with totals per day and per prompt.

## Feedback

If you notice any accessibility issues while using the software, please, give us feedback by either contacting the support email at [grp-toska+currechat@helsinki.fi](mailto:grp-toska+currechat@helsinki.fi) or by [creating an issue in GitHub](https://github.com/UniversityOfHelsinkiCS/gptwrapper/issues/new). We are glad to receive suggestions on how to improve the accessibility of CurreChat.

If you are not satisfied with the answer or do not receive an answer within two weeks, you may [submit a complaint](https://www.saavutettavuusvaatimukset.fi/en/user-rights/submit-complaint-web-accessibility-or-request-clarification) to the Finnish Transport and Communications Agency Traficom. The linked Traficom website contains information on how to submit a complaint and how the matter is processed.
