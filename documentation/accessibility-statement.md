# Accessibility statement of CurreChat of the University of Helsinki

This accessibility statement applies to the accessibility of CurreChat, an AI chat service for teaching and studying, available at [curre.helsinki.fi](https://curre.helsinki.fi). It also applies to CurreChat when it is embedded in Moodle. The document was created on 16 October 2026 and last updated on 19 October 2026. The accessibility analysis of the software was done by the developers using both automated tools ([WAVE Evaluation Tool](https://chrome.google.com/webstore/detail/wave-evaluation-tool/jbbplnpkjmmeebjpijfedlgcdilocofh) and [axe-core](https://github.com/dequelabs/axe-core) run with [Playwright](https://playwright.dev/)) and manual testing methods, including code review, keyboard testing and screen reader testing. In addition, the AI coding assistant [Claude Code](https://claude.com/claude-code) by Anthropic was used to support the evaluation, for example in reviewing the source code against WCAG requirements and in identifying accessibility issues. All findings were verified by the developers.

## Accessibility status

The system partially meets the A and AA level accessibility requirements of the Web Content Accessibility Guidelines (WCAG) 2.1. The accessibility deficiencies identified are described in detail below.

Accessibility work has so far focused on the student views: the general chat, the course chat, the prompt and model selection, creating and editing personal prompts, and the settings, feedback and disclaimer dialogs. The teacher/employee views (course management, prompt and source material editing, course statistics) are being worked on right now. The admin and statistics views have not yet been systematically evaluated.

## Accessibility issues

This list includes the issues that have been identified in the accessibility evaluation in autumn 2026. Unless stated otherwise, an issue affects all users. Issues marked _teachers and admins_ only concern views that students cannot access. The evaluation is still in progress and the developers are actively working towards remediating the issues.

### Perceivability issues

- **Non-text content**: Charts are not accessible. The prompt usage chart in the course view has no text alternative or data table, and its values can only be read by hovering with a mouse. (WCAG 1.1.1) _Teachers and admins._
- **AI-generated content**: Answers in the chat are generated by an AI model, and the developers cannot fully control their structure. Mathematical formulas are rendered with KaTeX and are also provided as MathML, but they are not read correctly by all screen readers. Formulas that fail to render are shown as raw LaTeX code. (WCAG 1.1.1, 1.3.1)
- **Use of colour**: In the usage trend chart on the statistics page and the prompt usage chart in the course view, the data series are distinguished by colour alone. In the prompt usage chart, the colours repeat when a course has many prompts, so different prompts can have the same colour. (WCAG 1.4.1) _Teachers and admins._
- **Contrast**: Some texts and icons in the source material views do not have enough contrast. In dark mode, the RAG search field has almost no contrast, and error and warning texts do not have enough contrast. (WCAG 1.4.3) _Mainly teachers and admins._

### Operability issues

- **Keyboard**: Notifications (snackbars) cannot be reached with a keyboard or a screen reader while a dialog is open. (WCAG 2.1.1)
- **Timing adjustable**: Notifications (snackbars) disappear automatically after about 20 seconds. The timer pauses while the keyboard focus or the mouse is on a notification, but it does not pause while a screen reader user reads the page with the virtual cursor, and the time limit cannot be turned off or extended. Notifications are not stored anywhere after they disappear. At most four notifications are shown at a time: when a fifth one arrives, the oldest disappears immediately and can no longer be focused or read. (WCAG 2.2.1)
- **Focus order**: The keyboard focus does not always behave as intended. Focus can be lost (moved to the beginning of the page) when the button that had focus disappears. Examples: the "Retry" button after an error, the "Stop" button when an answer finishes, closing a notification banner, the oldest notification disappearing, switching between the discussion list and a single discussion, and editing in the course creator. Notifications appear at the top of the screen but come last in the focus order. (WCAG 2.4.3)

### Understandability issues

- **Language of page**: The language of the page is always set to English, even when the user interface is in Finnish or Swedish. Screen readers may therefore read Finnish and Swedish texts with English pronunciation. (WCAG 3.1.1)
- **Language of parts**: Some content is in a different language from the page, and this cannot be programmatically determined. This includes some English texts that have not been translated, the language options in the language menu, and AI answers written in a different language from the user interface. (WCAG 3.1.2)
- **Error identification**: In some forms, errors are shown only in a notification and the invalid field is not marked. Examples: saving a prompt, managing notifications, and creating source material. Invalid dates in the course activity period are ignored without an error message. (WCAG 3.3.1, 3.3.3) _Mainly teachers and admins._
- **Labels or instructions**: In the chat, the message field's only label is its placeholder text, and the instructions for sending (Enter or Shift+Enter) are not connected to the field. In the teacher and admin views, some search fields and selects have no label or only a placeholder. (WCAG 3.3.2)

### Robustness issues

- **Name, role, value**: On mobile screens and in Moodle, the "Open sidebar" and "New conversation" buttons have no accessible name. In the teacher and admin views, some icon buttons, selects and progress bars have no accessible name. Sortable table columns do not tell screen readers how they are sorted, and the selected source material collection is not shown to them. The embed code that teachers copy into Moodle creates an iframe with no title. (WCAG 4.1.2)
- **Status messages**: Some screen readers may read some messages twice. For example, when generating an answer fails, the error can be announced several times, and new notifications are read together with recent ones. Notification banners interrupt the screen reader every time a page is loaded, even when their content is static. Some status messages are not announced at all: "Copied" after copying, the progress of searching source materials, search result counts in the teacher and admin views, and processing progress of uploaded source material. (WCAG 4.1.3)

### Accessibility features already in place

To help users, the following features have been implemented:

- While an answer is being generated, its status (processing, writing, ready, cancelled, failed) is announced to screen readers. The answer text itself is not read out piece by piece.
- A "Skip to content" link at the start of every page moves the keyboard focus past the header, and in the chat also past the sidebar. The sidebar is marked as a landmark.
- The "Skip to latest response" button moves the keyboard focus to the newest answer.
- Mathematical formulas in AI answers are also provided as MathML for screen readers.
- The user can choose whether Enter or Shift+Enter sends a message.
- A dark mode is available in the settings.
- All interactive elements have a visible keyboard focus indicator, and it has enough contrast in both light and dark mode.
- The selected tab, the usage gauge and the colours, axes and legends of charts have enough contrast in both light and dark mode.
- Notifications are announced to screen readers, also while a dialog is open.

## Feedback

If you notice any accessibility issues while using the software, please, give us feedback by either contacting the support email at [grp-toska+currechat@helsinki.fi](mailto:grp-toska+currechat@helsinki.fi) or by [creating an issue in GitHub](https://github.com/UniversityOfHelsinkiCS/gptwrapper/issues/new). We are glad to receive suggestions on how to improve the accessibility of CurreChat.

If you are not satisfied with the answer or do not receive an answer within two weeks, you may [submit a complaint](https://www.saavutettavuusvaatimukset.fi/en/user-rights/submit-complaint-web-accessibility-or-request-clarification) to the Finnish Transport and Communications Agency Traficom. The linked Traficom website contains information on how to submit a complaint and how the matter is processed.
